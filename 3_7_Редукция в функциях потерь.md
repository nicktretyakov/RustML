# **Редукция в функциях потерь**
Редукция (reduction) — это как свернуть вектор поэлементных потерь в одно число: сумму, среднее или «сырую» сумму без усреднения.
В проекте это сделано по аналогии с torch.nn.functional (reduction='mean' | 'sum' | 'none').

Редукция — это enum None / Mean / Sum и функция compute_reinforce_loss, которая суммирует по траектории и при Mean делит на число шагов. Loss используется для отчёта; обучение идёт через явные градиенты в reinforce_step, поэтому выбор reduction влияет на метрики, а не на формулу шага оптимизатора напрямую.

1. Enum Reduction

```
#[derive(Clone, Copy, PartialEq, Debug)]
pub enum Reduction {
    None,  // сырая сумма (без деления)
    Mean,  // среднее по длине траектории / «батча»
    Sum,   // сумма
}

```


В этом коде None и Sum дают одно и то же число (сумму). В PyTorch 'none' обычно возвращает тензор поэлементных loss; здесь для мониторинга достаточно скаляра, поэтому None = «не усреднять».

2. Функция потерь REINFORCE


```
pub fn compute_reinforce_loss(
    log_probs: &[f32],     // log π(a_t | s_t)
    advantages: &[f32],    // G_t (или advantage)
    reduction: Reduction,
) -> f32
```

Поэлементный член

total_loss += -logp * adv;

Это классический policy gradient loss (REINFORCE).

Редукция после суммы

```
match reduction {
    Reduction::None => total_loss,
    Reduction::Mean => {
        if log_probs.is_empty() { 0.0 }
        else { total_loss / log_probs.len() as f32 }
    }
    Reduction::Sum => total_loss,
}
```

Проверка assert_eq!(log_probs.len(), advantages.len()) — длины должны совпадать.

3. Откуда берутся log_probs и advantages

В collect_and_compute_loss / train_episode:

1. Сбор траектории


```
let probs = self.forward(&state)?;
let action = if probs[0] > probs[1] { 0 } else { 1 };
let log_prob = probs[action].ln();   // log π(a|s)
// step → reward
trajectory.push((state, action, reward, log_prob));
```

2. Дисконтированные returns


```
let mut g = 0.0;
for i in (0..trajectory.len()).rev() {
    g = trajectory[i].2 + gamma * g;  // r_t + γ G_{t+1}
    returns[i] = g;
}
```


В упрощённом REINFORCE advantage ≈ return (advantages = returns).

3. Loss с разными reduction


```
let loss_mean = compute_reinforce_loss(&log_probs, &advantages, Reduction::Mean);
let loss_sum  = compute_reinforce_loss(&log_probs, &advantages, Reduction::Sum);
let loss_none = compute_reinforce_loss(&log_probs, &advantages, Reduction::None);
```

В train_episode для лога обычно берут Mean:
```
let loss = compute_reinforce_loss(&log_probs, &returns, Reduction::Mean);

```

4. Важный момент: loss ≠ градиентный шаг

compute_reinforce_loss только считает скаляр для мониторинга.

Обновление весов идёт отдельно в reinforce_step:


```
for (t, (state, action, _, _)) in trajectory.iter().enumerate() {
    self.reinforce_step(state, *action, returns[t], lr)?;
}
```

Там аналитический градиент:

reduction не масштабирует learning rate автоматически. Если бы loss шёл в autograd-оптимизатор, Mean vs Sum менял бы эффективный LR; здесь шаг задаётся явно через lr.

Зачем тогда reduction?

сравнивать эпизоды разной длины (Mean честнее, чем Sum);

логировать «средний loss на шаг»;

повторить API PyTorch в учебном коде.


5. Пример на числах

Траектория из 3 шагов:

Sum / None = $1.0 + 1.0 + 0.1 = 2.1$

Mean = $2.1 / 3 = 0.7$

При длинном эпизоде Sum растёт с числом шагов, Mean — сопоставим между эпизодами.

6. Связь с Tensor reductions

В модуле тензоров есть другие редукции (sum, mean, max по элементам тензора) — это операции над данными, не loss API.
Loss-редукция — отдельный enum Reduction + compute_reinforce_loss.

7. Схема потока

Эпизод в CatEnv

    │

    ▼

trajectory: (state, action, reward, log_prob)×T

    │

    ▼

returns G_t (γ-дисконт с конца)

    │

    ▼

compute_reinforce_loss(log_probs, G, reduction)

    │

    ├─ Mean  → скаляр для лога / сравнения

    ├─ Sum   → сумма по шагам

    └─ None  → то же, что Sum (в этой реализации)

    │

    └── параллельно: reinforce_step(..., G_t, lr)  // реальное обучение
