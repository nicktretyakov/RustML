# **Обработка ошибок в ML-пайплайнах**
В проекте используется явная модель ошибок Rust: Result<T, E> вместо исключений. Центр — enum AppError, через который проходят почти все ML/RL-операции.

Обработка ошибок построена на AppError + Result + ?. Enum покрывает IO, валидацию, размерности, тензоры, spaces, аугментации и сериализацию; Display/Error/From дают удобный проброс и печать. Критические пути ML-пайплайна не паникуют, а возвращают типизированную ошибку наверх — в духе идиоматичного Rust и устойчивых ML-пайплайнов.


1. Центральный тип: AppError

```
pub enum AppError {
    Io(std::io::Error),
    Parse(String),
    Validation(String),
    DimensionMismatch(String),
    EmptyTensor(String),
    InvalidState(String),
    Preprocessing(String),
    Postprocessing(String),
    AugmentationError(String),
    SpaceError(String),
    SerializationError(String),
}

```

Io чтение/запись файлов (save/load, CSV)

Parse разбор строк/конфигов

Validation невалидные данные (имя,lives)

DimensionMismatch несовпадение размеров тензоров / matmul

EmptyTensor пустой вход в forward / norm

InvalidState некорректное состояние пайплайна

Preprocessing ошибки предобработки

Postprocessing ошибки интерпретации выхода

AugmentationError пустой state при аугментации

SpaceError observation/action вне Space

SerializationError пустой/битый файл модели

Каждый вариант несёт сообщение (String) или обёртку (std::io::Error).

2. Трейты: Display, Error, From

```
impl fmt::Display for AppError { ... }  // человекочитаемый текст
impl Error for AppError {}              // стандартный error trait

impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> Self { AppError::Io(e) }
}

impl From<String> for AppError {
    fn from(s: String) -> Self { AppError::Validation(s) }
}

```

Зачем:

Display — println!("{}", e), логи;

Error — совместимость с Box<dyn Error>, экосистемой Rust;

From — оператор ? сам превращает io::Error / String в AppError.


3. Паттерн Result по слоям

Почти все «опасные» методы возвращают Result:

Тензоры add/sub/mul/div → Result<Tensor, AppError>

Dense forward → Result<Vec<f32>, AppError>

Сеть forward_multi_task, reinforce_step, train_episode

Аугментации 	augment → Result<Vec<f32>, AppError>

Сериализация save / load → Result<(), AppError>

Часть «доменных» API ещё на Result<T, String>:
```
Cat::new(...) -> Result<Self, String>
interpret_prediction(...) -> Result<String, String>

```

Их можно поднять в AppError через From<String> или .map_err(...).

4. Оператор ? — основной стиль

Типичный forward:

```
pub fn forward_multi_task(&self, state: &[f32]) -> Result<MultiTaskOutput, AppError> {
    if state.is_empty() {
        return Err(AppError::EmptyTensor("...".into()));
    }
    // ...
    let mut x = self.layer1.forward(&input_state)?;  // проброс ошибки вверх
    // ...
    let logits = self.layer2_policy.forward(&x)?;
    Ok(MultiTaskOutput::new(policy, value, tree_value))
}
```

Цепочка:

mat_vec_mul  →  DenseLayer::forward  →  forward_multi_task  →  main

     Err?              ?                        ?                ?
     
Первая ошибка сразу возвращается вызывающему коду — без panic!.

5. Где ошибки создаются явно

Размерности (тензоры):

```
if self.data.len() != other.data.len() {
    return Err(AppError::DimensionMismatch(format!("add: {} != {}", ...)));
}

```

Пустой вход:


```
if input.is_empty() {
    return Err(AppError::EmptyTensor("DenseLayer::forward: пустой вход".into()));
}
```


RL spaces:


```
if !obs_space.contains(state) {
    return Err(AppError::SpaceError(format!(
        "Состояние {:?} не входит в observation_space {}",
        state, obs_space.description()
    )));
}
```


Аугментации:


```
if state.is_empty() {
    return Err(AppError::AugmentationError("Пустое состояние...".into()));
}
```


Файлы:


```
let mut f = File::create(path).map_err(AppError::Io)?;
// или через From: File::create(path)?;  если функция → Result<_, AppError>
```


Сериализация:


```
if lines.is_empty() {
    return Err(AppError::SerializationError("Файл модели пустой".into()));
}
```


6. Что делается без AppError

Не всё заворачивается в enum:

Cat::new Result<_, String>

div на ноль 0.0 вместо Err

mean/max на пустом default 0.0

FFI (cat_new) null при ошибке (C-стиль)

reinforce_step в Eval Ok(()) — тихий no-op

Невалидный action в step штраф −10 и done, не Err

FFI и среда иногда предпочитают «мягкий» отказ, чтобы не ронять процесс Python / эпизод.

7. Обработка наверху (main)

Типичный вид:
```
fn main() -> Result<(), Box<dyn Error>> {
    let multi = nn.forward_multi_task(&state)?;
    nn.save("cat_model.model")?;
    Ok(())
}

```
Или точечно:
```
match nn.load("no_such_model.model") {
    Ok(_) => println!("ok"),
    Err(e) => println!("Поймано: {}", e),  // Display
}

```

Box<dyn Error> принимает и AppError, и io::Error благодаря Error + From.

9. Связь с SOLID / слоями

Preprocessing Validation, EmptyTensor

Spaces SpaceError

Tensor / Dense DimensionMismatch, EmptyTensor

Augmentation AugmentationError

Postprocessing Postprocessing (через String/Result)

Serialization Io, SerializationError

Ошибки типизированы по домену, а не одним общим String — проще логировать и реагировать.
