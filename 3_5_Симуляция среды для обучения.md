# **Симуляция среды для обучения с подкреплением (RL)**

Далее необходима симуляция среды для обучения - например среда, где агент может взаимодействовать с котом (кормить, играть), изменяя количество жизней.

Среда построена по образцу OpenAI Gym / Gymnasium: агент видит состояние, выбирает действие, получает награду и флаг конца эпизода. «Мир» — кот с жизнями; действия — кормить или играть.

RL-среда — это CatEnv вокруг Cat: Gym-интерфейс reset/step, пространства Discrete/Box, два действия с явной таблицей наград, терминация по смерти или лимиту шагов. Агент (CatPolicyNetwork) читает observation, выбирает action, получает reward и по траектории обновляет policy — классический учебный REINFORCE-цикл на минимальной MDP.


1. Идея среды

Действия Feed (0), Play (1)

Награда +1 / −1 за feed, +0.5 / −2 за play

Конец эпизодакот «умер» (lives == 0) или max_steps

Интерфейс reset() / step(action) → (obs, reward, done, info)



2. Пространства (Space)


```
pub enum Space {
    Discrete { n: usize },           // действия
    Box { low: Vec<f32>, high: Vec<f32> },  // наблюдения
}
```

В CatEnv:

observation_space: Space::Box { low: vec![0.0], high: vec![1.0] },

action_space:      Space::Discrete { n: 2 },

Методы:

sample() случайный элемент (exploration / отладка)

contains(value) проверка валидности

description() строка для логов

Это контракт: что можно наблюдать и что можно делать — как в Gymnasium.

3. Действия (Action)

```
pub enum Action {
    Feed = 0,
    Play = 1,
}

```

from_u8 — разбор ввода (0/1);

as_usize — для проверки action_space и индексов policy.


4. Физика мира — методы Cat


```
fn feed(&mut self) -> (bool, f32) {
    if self.lives < 9 {
        self.lives += 1;
        (true, 1.0)    // успех
    } else {
        (false, -1.0)  // уже 9 жизней
    }
}

fn play(&mut self) -> (bool, f32) {
    if self.lives > 1 {
        self.lives -= 1;
        (true, 0.5)
    } else {
        (false, -2.0)  // опасно играть при 1 жизни
    }
}
```


Feedlives < 9 +1.0 +1 жизнь

Feedlives == 9 −1.0 без изменений 

Playlives > 1 +0.5 −1 жизнь

Playlives ≤ 1 −2.0 без изменений (или близко к смерти)

Награда сразу кодирует «хорошо/плохо» — классический dense reward для REINFORCE.

Состояние для сети:


```
fn get_state(&self) -> Vec<f32> {
    vec![self.lives as f32 / 9.0]
}
```


Один непрерывный признак — упрощённая MDP с маленьким state space.


5. CatEnv — обёртка Gym-like

```
pub struct CatEnv {
    cat: Cat,
    step_count: usize,
    max_steps: usize,              // по умолчанию 50
    pub observation_space: Space,
    pub action_space: Space,
}

```

Создание


```
CatEnv::new(cat)           // конкретный кот
CatEnv::random()           // Cat::random()
CatEnv::with_name("Murka") // lives = 9

pub fn reset(&mut self) -> Vec<f32> {
    self.cat.lives = 9;
    self.step_count = 0;
    self.cat.get_state()
}
```

Начало эпизода: полные жизни, счётчик шагов обнулён, возвращается observation.

step — главный шаг симуляции


```
pub fn step(&mut self, action: Action) -> StepResult {
    // 1. Невалидное действие → штраф и конец
    if !self.action_space.contains(&[action.as_usize() as f32]) {
        return StepResult {
            observation: self.cat.get_state(),
            reward: -10.0,
            done: true,
            info: "Invalid action".into(),
        };
    }

    // 2. Учёт шага
    self.step_count += 1;

    // 3. Применение действия к коту
    let (success, reward) = match action {
        Action::Feed => self.cat.feed(),
        Action::Play => self.cat.play(),
    };

    // 4. Терминальное условие
    let done = !self.cat.is_alive() || self.step_count >= self.max_steps;

    // 5. Gym-кортеж
    StepResult {
        observation: self.cat.get_state(),
        reward,
        done,
        info: format!("action={:?}, success={}, lives={}, step={}", ...),
    }
}
```

StepResult — аналог (obs, reward, terminated, truncated, info) в современном Gym, здесь done объединяет terminated/truncated.

Вспомогательные методы

observation() текущий state без шага

is_done()проверка конца эпизода

cat() / cat_mut()доступ к сущности

interactive_loop()человек вводит 0/1 с клавиатуры

run_random_episode()случайная политика (baseline)


6. Цикл «агент ↔ среда»

Типичный эпизод (как в run_episode / train_episode):

reset() → obs₀

    │
    
    ▼
    
пока not done:

    policy(obs) → action          # CatPolicyNetwork
    
    step(action) → obs', r, done
    
    сохранить (obs, action, r)    # trajectory
    
    obs ← obs'
    
    │
    
    ▼
    
подсчёт returns G_t (γ = 0.99)

обновление весов (REINFORCE)      # только Train

Схема взаимодействия:

┌─────────────────┐     action      ┌──────────────┐

│ CatPolicyNetwork│ ──────────────► │   CatEnv     │

│  (агент)        │ ◄────────────── │  (среда)     │

└─────────────────┘  obs, reward,    └──────┬───────┘

                      done                  │

                                            ▼

                                         Cat

                                    (lives, feed/play)

Eval: только select_action + step, веса не трогаются.

Train: после эпизода reinforce_step по траектории.



7. Награды и цель обучения

Агент учится максимизировать сумму наград за эпизод.

Интуиция политики:

при высоких lives — можно чаще play (риск ниже);

при низких — чаще feed, иначе штраф −2 и смерть;

при lives == 9 feed даёт −1 → политика должна избегать бесполезного feed.


Дисконт gamma (из Hyperparams, обычно 0.99) учитывает будущие награды при подсчёте $G_t$.


8. Связь с пространствами и сетью

env.observation() → вектор в observation_space.

forward_multi_task проверяет Space::contains.

Softmax → [p_feed, p_play].

select_action → Action.

env.step проверяет action_space.


Среда и агент согласованы через одни и те же пространства.

9. Интерактивный режим

interactive_loop — среда без нейросети:

State: lives = 9 | Action (0/1): 1

  → reward = 0.5, done = false, info = action=Play, ...
Удобно отладить reward-функцию руками.


10. Ограничения модели мира

State = 1 число MDP очень простой

2 дискретных действия tabular-подобная задача

Детерминированные переходы нет stochasticity среды

Dense reward каждый шаг REINFORCE сходится быстрее

max_steps = 50 эпизод не бесконечный
