# **Конфигурации моделей / архитектур (закрытый набор)**
Конфигурации моделей — это закрытый enum ModelArchitecture (SimpleMLP, DeepMLP, ActorCritic, HybridTreeNN, Tiny) с методом hidden_sizes(), плюс ModelConfig, объединяющий архитектуру, dtype, device и hyperparams. from_config по вектору размеров строит layer1, layer_hidden и единые policy/value heads — одна структура сети, пять предопределённых профилей, без свободной «сборки с нуля».

В проекте архитектура сети не собирается произвольными размерами слоёв. Есть закрытый набор (enum) из пяти готовых вариантов плюс единый ModelConfig, который связывает архитектуру с dtype, device и гиперпараметрами.

1. Идея «закрытого набора»

```
pub enum ModelArchitecture {
    SimpleMLP,
    DeepMLP,
    ActorCritic,
    HybridTreeNN,
    Tiny,
}

```
Это model zoo в миниатюре:

нельзя указать «сеть 1→32→16→8» произвольным конструктором;
только один из пяти именованных профилей;
каждый профиль однозначно задаёт hidden_sizes().

Плюсы: предсказуемость, проще сериализация, меньше ошибок конфигурации.

Минусы: нет свободной кастомной топологии без правки enum.

2. ModelArchitecture — методы

description()

Человекочитаемые строки:

SimpleMLP 1 → 8 → policy/value

DeepMLP 1 → 16 → 8 → policy/value

ActorCritic shared backbone + heads

HybridTreeNN NN + DecisionTree

Tiny 1 → 4 → policy/value


hidden_sizes() -> Vec<usize>

```
SimpleMLP     => [8]
DeepMLP       => [16, 8]
ActorCritic   => [16, 8]
HybridTreeNN  => [12, 8]
Tiny          => [4]

```

Этот вектор — единственный источник правды о ширине скрытых слоёв при сборке сети.

3. ModelConfig — всё в одном месте

```
pub struct ModelConfig {
    pub architecture: ModelArchitecture,
    pub dtype: DType,           // Float32 / Float16 / Int8
    pub device: Device,         // Cpu / Gpu / Metal
    pub hyperparams: Hyperparams, // lr, gamma, scheduler, ...
}

```

Default:


```
architecture: SimpleMLP
dtype:        Float16
device:       Cpu
hyperparams:  Hyperparams::default()
```


Один объект покрывает «что за сеть», «на чём считать», «с какой точностью» и «как учить».

4. Сборка сети из конфига: from_config


```
pub fn from_config(config: ModelConfig) -> Self
```

Алгоритм:

config.print() — лог настроек.

hidden = config.architecture.hidden_sizes().

first_size = hidden[0], last_size = hidden.last().

layer1: Dense(1 → first_size) — вход всегда 1 (норм. lives).

layer_hidden: для каждой пары соседних размеров	
windows(2) → Dense(w[0] → w[1]).

[8] → дополнительных hidden нет;

[16, 8] → один слой 16→8;

и т.д.

Heads (одинаковы для всех архитектур):

layer2_policy: last_size → 2 (Softmax снаружи);

layer_value: last_size → 1.


DecisionTree — сейчас создаётся почти для всех вариантов как auxiliary (fit на простых state→target).

Поля dtype, device, architecture, hyperparams копируются в CatPolicyNetwork; mode = Train; augmenter = Some(default).

Итог: одна структура CatPolicyNetwork представляет пять разных глубин за счёт layer_hidden: Vec<DenseLayer>.

5. Как это выглядит для разных архитектур

textTiny:        1 → [4]           → policy(2), value(1)

SimpleMLP:   1 → [8]           → policy, value

DeepMLP:     1 → [16] → [8]    → policy, value

ActorCritic: 1 → [16] → [8]    → policy, value  (+ смысл AC)

HybridTreeNN:1 → [12] → [8]    → policy, value  + tree
	
В forward_multi_task цикл:

```
x = layer1.forward(...)
// LayerNorm + ReLU
for layer in &self.layer_hidden {
    x = layer.forward(&x)?;
    // LayerNorm + ReLU
}
// heads...

```

Число итераций = hidden.len() - 1 (число рёбер между hidden-размерами).

6. Точки входа создания сети

CatPolicyNetwork::new() ModelConfig::default() 

new_with_dtype(dtype) default + свой dtype

new_with_config(dtype, hyperparams) default + dtype + hyperparams

from_config(config) полный контроль

Пример смены архитектуры:

```
let cfg = ModelConfig {
    architecture: ModelArchitecture::DeepMLP,
    device: Device::Gpu,
    dtype: DType::Float32,
    hyperparams: Hyperparams::default(),
};
let nn = CatPolicyNetwork::from_config(cfg);

```

7. Сериализация

В save пишется, среди прочего:

architecture: DeepMLP

device: Gpu

dtype: Float32

Архитектура — часть идентичности модели: при загрузке можно восстановить, какая топология была (полная реконструкция слоёв из файла в учебной версии может быть упрощена).

8. Связь с SOLID

OCP новый профиль = новый вариант enum + ветка в hidden_sizes, без ломки from_config

SRPModelArchitecture — только топология; ModelConfig — сборка настроек; сеть — вычисления

DIP обучение/forward зависят от абстракции «архитектура → sizes», а не от хардкода 8 нейронов
