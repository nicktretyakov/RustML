# **Постобработка результатов (Postprocessing)**

Далее лучше реализовать постобработку результатов - например интерпретацию выхода ML-модели (например, вероятности) и вызов meow().

Постобработка — это всё, что происходит после сырого выхода модели (логиты / вероятности / value), чтобы получить:

понятный человеку текст;

дискретное действие для среды;

структурированный multi-task результат.


1. Softmax — перевод логитов в вероятности

Сырой выход линейного слоя — логиты (ненормированные числа).

Первый шаг постобработки — сделать из них вероятности:


```
pub fn softmax(input: &[f32]) -> Vec<f32> {
    let max_val = *input.iter().max_by(|a, b| a.partial_cmp(b).unwrap()).unwrap();
    let exps: Vec<f32> = input.iter().map(|&x| (x - max_val).exp()).collect();
    let sum_exp: f32 = exps.iter().sum();
    exps.into_iter().map(|e| e / sum_exp).collect()
}
```


Особенности:

вычитание max_val — численная устойчивость (нет overflow у exp);

сумма вероятностей ≈ 1.0;

вызывается в конце policy head:

Rustlet logits = self.layer2_policy.forward(&x)?;

let policy = softmax(&logits);  // [p_feed, p_play]

Без Softmax argmax по логитам формально тоже работает, но для loss
(REINFORCE) и интерпретации нужны именно вероятности.

2. MultiTaskOutput — структурированный результат модели
 
```
pub struct MultiTaskOutput {
    pub policy: Vec<f32>,        // [p_feed, p_play]
    pub value: f32,              // оценка состояния
    pub tree_value: Option<f32>, // auxiliary от DecisionTree
}

```

Это первый уровень постобработки на стороне сети:

Policy head → Softmax → policy

Value head → скаляр → value (без Softmax, регрессия)

DecisionTree → tree_value (если есть)


Один вызов forward_multi_task возвращает всё сразу — удобно и для RL, и для отладки.


```
let multi = nn.forward_multi_task(&state)?;
// multi.policy, multi.value, multi.tree_value
pub fn forward(&self, state: &[f32]) -> Result<Vec<f32>, AppError> {
    let multi = self.forward_multi_task(state)?;
    Ok(multi.policy)
}
```


3. select_action — вероятности → дискретное действие


```
pub fn select_action(&self, state: &[f32]) -> Result<Action, AppError> {
    let multi = self.forward_multi_task(state)?;
    Ok(if multi.policy[0] > multi.policy[1] {
        Action::Feed
    } else {
        Action::Play
    })
}
```


Это классический argmax postprocessing:

policy[0] > policy[1]

да

Action::Feed

нет

Action::Play
	
Дальше действие уходит в среду:

let action = nn.select_action(&state)?;

let result = env.step(action);  // observation, reward, done, info

В run_episode / train_episode тот же принцип: 
probabilities → index → Action.

4. interpret_prediction — вероятности → человекочитаемый текст

На Cat (классификационный сценарий happy/grumpy):


```
pub fn interpret_prediction(&self, probabilities: &[f32]) -> Result<String, String> {
    if probabilities.len() < 2 {
        return Err("Ожидалось минимум 2 вероятности [happy, grumpy]".into());
    }
    let (class, prob) = if probabilities[0] > probabilities[1] {
        ("happy", probabilities[0])
    } else {
        ("grumpy", probabilities[1])
    };
    Ok(format!(
        "{} is {} with confidence {:.2}",
        self.name, class, prob
    ))
}
```


Что делает постобработка:

Валидация длины выхода (>= 2).

Argmax по двум классам.

Форматирование с именем кота и confidence.


Пример:

Whiskers is happy with confidence 0.85

Ошибки идут через Result (AppError::Postprocessing на уровне enum ошибок пайплайна).


5. meow() — побочное действие после интерпретации

```
pub fn meow(&self) {
    println!("{} says meow! (lives: {})", self.name, self.lives);
}

```

В исходном примере это «дополнительное действие» после интерпретации:


```
let message = my_cat.interpret_prediction(&model_output);
println!("{}", message);
my_cat.meow();
```


В RL-цикле meow не обязателен, но в interactive-режиме среды и в демо он остаётся частью человеко-ориентированной постобработки (не влияет на градиенты).


6. Value и tree — другие «выходы» без Softmax

policy Softmax → argmax → Action / текст

value скаляр как есть (оценка будущей награды)

tree_value DecisionTree::predict → число
	
Value обычно сравнивают с returns при Actor-Critic; tree — вспомогательный сигнал. Оба уже «готовы» к использованию без дополнительной нормализации в текущей версии.

7. Полный путь: от логитов до действия/текста

Логиты policy head (2 числа)
        
        ▼
   Softmax  ──────────────────► [p_feed, p_play]
        
        ├──────────────────────► MultiTaskOutput.policy
                                      + value
                                      + tree_value
        
        ├─ select_action ──────► Action::Feed | Action::Play
                                      
                                      ▼
                                 env.step(action)
        
        └─ interpret_prediction ► "Murka is happy with confidence 0.91"
                                      ▼
                                    meow()  (опционально)

8. Где это в коде

Softmax softmax()

Сборка выходов forward_multi_task → MultiTaskOutput

Вероятности → действие select_action

Вероятности → текст Cat::interpret_prediction

Побочный эффектCat::meow

Тип ошибки AppError::Postprocessing

9. Связь preprocessing ↔ postprocessing

lives → lives/9.0 logits → Softmax

проверка Space argmax → Action

аугментация (Train) interpret_prediction → строка

Tensor + dtype MultiTaskOutput как контракт выхода

Вход модели нормализуется и проверяется; выход денормализуется в смысл (действие среды или фраза для человека).

Итог: постобработка в проекте — это цепочка
 Softmax → MultiTaskOutput → (argmax → Action | interpret → текст + meow). 
 
 Для RL главное — select_action и structured MultiTaskOutput;
 
  для демо/классификации — interpret_prediction и meow.
