**Стандартные потоки (std::thread) и примитивы синхронизации**

-   `Базовый механизм Rust: создание потоков через std::spawn`

создаётся новый поток, который печатает сообщение параллельно с основным потоком.

-   `Синхронизация через Mutex, RwLock, Arc, Barrier, Condvar`

    Когда несколько потоков работают с одними и теми же данными, может возникнуть хаос (race condition). Синхронизация нужна, чтобы потоки не мешали друг другу.

**`Mutex (Mutual Exclusion)`**`позволяет только одному потоку работать с данными в один момент. `

**Пример:** Один человек может пользоваться туалетом в самолете, остальные ждут.`

**`RwLock (Read-Write Lock)`**`позволяет нескольким потокам читать данные одновременно, но только одному — изменять.`

**Пример:** Многие могут читать книгу в библиотеке, но писать в ней может только один.`

**`Arc (Atomic Reference Counting)`**`позволяет нескольким потокам владеть одними и теми же данными.`

**Пример:** `Несколько человек могут держать одну и ту же карту, но не могут её порвать.`

**`Barrier`**`заставляет потоки ждать друг друга в определённой точке. 
**Пример:** `Все спортсмены стартуют только после выстрела.`

**`Condvar (Condition Variable)`**`позволяет потокам ждать, пока не наступит какое-то условие.`

**Пример:** `Официант не принесёт еду, пока не будет готов заказ.`

-   `Каналы для обмена сообщениями (std::sync::mpsc или crossbeam-channel).`

    Здесь один поток отправляет сообщение, а другой — принимает.

-   `В ML: используется для параллельного data loading, augmentation, простого многопоточного обучения (например, параллельный подсчёт градиентов в небольших моделях).`

**`Параллельная загрузка данных:`**`Один поток загружает данные, другой — обучает модель.`

**`Data augmentation:`**`Один поток изменяет изображения, другой — использует их для обучения.`

**`Параллельный подсчёт градиентов`**` Несколько потоков считают градиенты для разных частей модели, потом результаты объединяются`

**`Преимущество Rust`**`Rust гарантирует безопасность при работе с потоками благодаря системе владения (ownership) и проверке заимствований (borrow checker). Это значит, что ошибки типа "гонки данных" (data race) невозможны на этапе компиляции.`

**`Применение в ML`**`:`

-   `Параллельный data loading/augmentation`

-   `Параллельный подсчёт градиентов в простых моделях`

-   `Многопоточная предобработка батчей`

**`Зависимости`**`: `Только std (нет внешних crates).`

**`Пример`**`: `Параллельная обработка изображений (augmentation) в датасете.`

   

**Асинхронное программирование (async/.await)**



    Runtime (среда выполнения) — это программа, которая управляет выполнением асинхронного кода. Она отвечает за распределение задач, планирование их выполнения и работу с неблокирующим вводом-выводом (I/O).

-   **`Tokio`** —`Используется для создания асинхронных приложений, например, веб-серверов, клиентов для работы с сетью, обработки потоков данных.`

-   **`async-std`**` —`альтернатива Tokio, проще в использовании для начинающих.`

-   **`smol`**` —`лёгкий и быстрый runtime, часто используется для небольших проектов.`

    Представьте, что вы готовите завтрак: тосты, кофе и яичницу. Вместо того чтобы ждать, пока тосты поджарятся, вы ставите их в тостер, включаете кофеварку и начинаете жарить яичницу. Runtime — это ваш помощник, который следит, чтобы всё готовилось параллельно и ничего не подгорело.

-   `Фьючерсы и executors для неблокирующего I/O.`

**`Фьючерс (Future)`**` — `это обещание, что какая-то операция завершится в будущем и вернёт результат. Например, загрузка файла из интернета`

**`Executor`**` — `это часть runtime, которая запускает и управляет выполнением фьючерсов.`

    Вы заказали пиццу по телефону. Оператор сказал: «Ваша пицца будет через 30 минут». Это и есть фьючерс — обещание, что пицца приедет. Курьер (executor) следит, чтобы заказ доставили вовремя и не заблудился по дороге.

-   `В ML: идеально для I/O-bound задач — асинхронная загрузка данных из сети/диска, streaming датасетов, работа с веб-API (например, скачивание моделей)`

    Задачи, которые тратят много времени на ожидание данных извне: загрузка файлов, обращение к базе данных, работа с сетью.

    Вы скачиваете большой файл из интернета. Компьютер не нагружает процессор, а просто ждёт, когда данные придут по сети. Это и есть I/O-bound задача.

    Асинхронность позволяет не ждать завершения одной операции, а переключаться на другие задачи. Например:

-   `Загружать данные с диска, пока обрабатываете уже загруженные.`

-   `Скачивать модель машинного обучения, пока готовите данные для неё.`

-   `Получать данные из API, не блокируя работу программы.`

    Вы смотрите фильм онлайн. Видео подгружается по частям (стриминг), и вы не ждёте, пока загрузится весь фильм, а смотрите его по мере загрузки.

-   `Популярные crates: tokio::task, futures, async-stream.`

    Если вы пишете программу для скачивания картинок с сайта, то tokio::task поможет запустить несколько скачиваний одновременно, а async-stream — обработать их по мере поступления.

-   `Часто комбинируется с rayon для смешанных сценариев.`

    Rayon — библиотека для параллельных вычислений (CPU-bound задач). Асинхронность (I/O-bound) + rayon (CPU-bound) = максимальная эффективность.

    Вы скачиваете данные (асинхронно) и одновременно обрабатываете их на процессоре (параллельно с rayon).

**`Применение в ML`**`:`

-   `Асинхронная загрузка данных из сети/диска`

-   `Streaming больших датасетов`

-   `Параллельные запросы к API (скачивание моделей, данных)`

**`Зависимости`**:`tokio = { version = "1", features = ["full"] }`

**`Пример`**`: `Асинхронная загрузка нескольких файлов датасета.`

    

**Data parallelism через Rayon**

-   `Crate: rayon (параллельные итераторы).`

-   `Методы: .par_iter(), .par_chunks(), parallel_scope.`

-   `В ML: самый распространённый способ для CPU-параллелизма.`

    -   `Параллельная предобработка датасетов (ndarray, polars, linfa).`

    -   `Параллельный feature engineering, cross-validation.`

    -   `Многие ML-библиотеки (linfa, smartcore, ndarray) имеют интеграцию или рекомендуют rayon.`

-   `Преимущество: минимальные изменения кода (замена iter() на par_iter()).`

**`Применение в ML`**: `Самый популярный способ для CPU-параллелизма:`

-   `Предобработка датасетов (ndarray, polars)`

-   `Feature engineering`

-   `Cross-validation`

-   `Параллельные вычисления в linfa/smartcore`

**`Зависимости`**`: rayon = "1.10"`

**`Пример`**: `Параллельное вычисление расстояний в k-NN.`

    

**GPU-параллелизм и ускорение на ускорителях**

-   **`rust-cuda / cust`**: `прямой доступ к CUDA API.`

-   **`vulkano`**: `безопасные Vulkan-биндинги.`

-   **`wgpu`**`: `современный кросс-платформенный API (WebGPU), подходит для compute shaders.`

-   **`arrayfire-rust`**: `высокоуровневая библиотека для массивов на CPU/GPU.`

-   **`tch-rs`**` (bindings ``к`` LibTorch): `использует встроенный параллелизм PyTorch (CUDA + cuDNN + многопоточность).`

-   **`burn`**`: `новый фреймворк ML в Rust с бэкендами wgpu, CUDA, Metal.`

-   `В ML: ускорение матричных операций, обучение нейросетей, инференс на GPU.`

-   `Это основной способ model parallelism и data parallelism на ускорителях.`

**`Применение в ML`**`: `Матричные операции, обучение/инференс нейросетей.`

**`Зависимости`**` (для burn): burn = { version = "0.13", features = ["wgpu"] }`

**`Пример`**`(burn + wgpu): Простая матричная операция на GPU.`

    
**Биндинги к внешним высокопроизводительным библиотекам**

-   **`tch-rs`**` (LibTorch): весь параллелизм берётся из PyTorch — многопоточный CPU + CUDA.`

-   **`onnxrust`**` / `**`tract`**`: `инференс ONNX-моделей, частично использует многопоточность.`

-   **`dfdx`**`, `**`burn`**`: `современные фреймворки с поддержкой автодифференцирования и GPU-бэкендов.`

-   `Параллелизм наследуется от C++/CUDA библиотек.`

**`Применение в ML`**: `Полноценное обучение нейросетей с встроенным параллелизмом.`

**`Зависимости`**`: tch = "0.15"`

**`Пример`**` (tch-rs): `Простой forward pass с CUDA.`

    

**Распределённый параллелизм (distributed)**

-   `Через сетевые crates: tokio + tonic (gRPC), actix-web, или raw TCP.`

-   `MPI-биндинги (mpi crate).`

-   `Специализированные проекты: juice (distributed ML в Rust), или кастомные реализации parameter server.`

-   `В ML: data parallelism и model parallelism между узлами (например, обучение больших моделей на кластере).`

-   `Пока менее зрело, чем в Python (Horovod, Ray), но активно развивается.`

**`Применение в ML`**`: Data/model parallelism для больших моделей.`

**`Зависимости`**`: tonic = "0.11", tokio = { features = ["full"] }`

**`Пример`**: `Простой gRPC-сервер для агрегации градиентов (очень упрощённо).
(Полный пример слишком длинный, но идея: каждый worker отправляет градиенты на сервер, сервер усредняет и рассылает обратно.)`
