# Обмен данными + ML-защита от аномалий
**Запустим вместе все микросервисы**

backend_ui Веб-дашборд (формы, таблицы)→ P2PBlockchain (/chain, /products, /submit_tx) → interop_ml (/validate).

P2PBlockchain P2P-нода + REST API← backend_ui (дашборд, транзакции) → interop_ml (/validate для ML-проверки перед мемпулом) ← interop_ml (GET /iot/temperature) P2P с другими нодами.

interop_ml ML-валидация (ансамбль + LOF)← P2PBlockchain / backend_ui (/validate) → P2PBlockchain (GET /iot/temperature) Локально использует contextML для GPU-LOF.

contextML — Библиотека (не сервис) Локально внутри interop_ml (GPU-ускорение LOF).

Поток данных ML:

    1. Пользователь в backend_ui отправляет транзакцию/данные температуры.
    
    2. backend_ui → P2PBlockchain (/submit_tx).
    
    3. P2PBlockchain → interop_ml (/validate): преобразование в ComplexData → признаки → нормализация Z-score → KNN (k=3) + дерево → энсамбль valid (согласие + label ≠ 0) → LOF (аномалии на GPU).
    
Преобразование в ComplexData: Данные (например, температура) превращаются в набор признаков (например, среднее, максимум, минимум за час).

Нормализация Z-score: Приводит все данные к одному масштабу, чтобы их было удобно сравнивать.

KNN (k=3) + дерево: Алгоритмы, которые ищут похожие данные и принимают решение на основе большинства.

Энсамбль valid: Если большинство алгоритмов согласны, что данные корректны, и метка (label) не равна 0 — данные считаются валидными.

LOF (аномалии на GPU): Ищет выбросы — данные, которые сильно отличаются от остальных (например, температура +100°C).

    4. Если valid && !anomaly — транзакция в мемпул → P2P-рассылка.
Мемпул: Это как очередь транзакций, которые ждут, когда их запишут в блокчейн.

P2P-рассылка: Все участники сети получают копию транзакции, чтобы проверить её и добавить в блокчейн.

    5. Если anomaly (LOF > порог) — rejected (защита от мошенничества/сбоев датчика).
    
Если алгоритм LOF находит аномалию (например, температура за пределами нормы), транзакция отклоняется, чтобы защититься от мошенничества или сбоев датчика.

    6. interop_ml периодически выполнякт GET /iot/temperature → мониторит аномалии температуры.
    
Система регулярно проверяет данные с датчиков температуры, чтобы вовремя заметить аномалии и предотвратить проблемы.

Система полностью распределённая, масштабируемая, 🚀 Запустите по порядку: P2PBlockchain → interop_ml → backend_ui.
