# **Выбор backend / устройства**
Выбор backend — enum Device { Cpu, Gpu, Metal } с методами описания и is_accelerated(). Устройство задаётся в ModelConfig, живёт в CatPolicyNetwork, меняется через to_device, пишется в файл модели.


Устройство задаёт где «логически» выполняется модель — по аналогии с torch.device, tch::Device, burn::tensor::Device. В учебном коде это симуляция: вычисления всегда на CPU (Vec<f32>), но API и конфигурация уже как у настоящих фреймворков.

1. Enum Device

```
pub enum Device {
    Cpu,    // обычный CPU
    Gpu,    // симуляция CUDA
    Metal,  // симуляция Apple Silicon / MPS
}

```


Методы

```
description()       // "CPU (...)", "GPU (симуляция CUDA)", ...
is_accelerated()    // true для Gpu | Metal

```
is_accelerated() — единая проверка «не CPU», без дублирования match


2. Где хранится устройство

В конфиге модели:

```
pub struct ModelConfig {
    pub architecture: ModelArchitecture,
    pub dtype: DType,
    pub device: Device,      // ← здесь
    pub hyperparams: Hyperparams,
}
```

По умолчанию: Device::Cpu.

В сети:


```
pub struct CatPolicyNetwork {
    // ...
    pub device: Device,
    // ...
}
```

При from_config / new_with_config поле копируется из ModelConfig.

В файле модели (save):

device: Cpu   // или Gpu / Metal

3. Переключение в runtime: to_device


```
pub fn to_device(&mut self, device: Device) {
    self.device = device;
    println!("🔄 Модель перемещена на: {}", device.description());
}
```

Аналог model.to("cuda") / tensor.to(device):


```
let mut nn = CatPolicyNetwork::from_config(cfg); // Cpu
nn.to_device(Device::Gpu);
nn.to_device(Device::Metal);
nn.to_device(Device::Cpu);
```

Веса не копируются в другую память (её нет) — меняется только метаданные устройства.

4. Использование в forward

В forward_multi_task:

```
if self.device.is_accelerated() {
    // В реальном tch-rs / burn: tensor.to(device)
    let _ = self.device;
}
```

Сейчас это:

точка расширения под настоящий перенос тензоров;

место для логов вида «выполнение на GPU»;

не меняет численный результат forward.

Все DenseLayer::forward, Softmax, LayerNorm по-прежнему на host f32.

5. Связь с остальным стеком

ModelConfig.device

        │

        ▼

CatPolicyNetwork.device

        │

        ├── to_device(...)     — смена в runtime

        ├── forward_multi_task — ветка is_accelerated()

        └── save/load          — сериализация метки

Рядом по смыслу:

DType как хранить числа (F32/F16/Int8)

Device 	где их считать (Cpu/Gpu/Metal)

ModelMode зачем (Train/Eval)

В production обычно: tensor.to(device).to(dtype).

6. Пример использования


```
let mut cfg = ModelConfig::default();
cfg.device = Device::Gpu;

let mut nn = CatPolicyNetwork::from_config(cfg);
println!("{}", nn.device.description()); // GPU (симуляция CUDA)

nn.to_device(Device::Metal);
// дальше train_episode / run_episode — те же формулы, другая метка
```
