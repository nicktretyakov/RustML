Для реализации решений с использованием ML необходимо постоянно выбирать между фреймворком
 и собственным решением.
В данном курсе рассмотрен необходимый теоретический и практический минимум для создания
 решений с ML уровня продакшен.
Поскольку существующие фреймворки обладают рядом недостатков:
    • Версионность, постоянно меняется API. 
    • Если функциональность не поддерживается фреймворком, нужно искать обходные пути.
    • Разные подходы к обучению моделей.
    • Отсутствие статического полиморфизма.
    • Отсутствие поддержки нужного железа.
    • Низкая производительность.
    • Сложная отладка.
    • Бедная экосистема.
Необходимо компромиссное решение для реализации конкретных задач ML.
В данном курсе рассмотрена реализация проекта от начальной стадии до продакшен, без использования фреймворков .
Яык Rust выбран для ML по следующим причинам:
    • Владение и заимствование — явно отражает перемещение данных.
    • Итераторы вместо циклов — стиль, близкий к функциональному программированию.
    • Клонирование строк — необходимо, чтобы владение предсказаниями было у вызывающего кода.
