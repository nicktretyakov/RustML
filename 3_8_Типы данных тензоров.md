DType — имитация tch::Kind / burn::tensor::DType / torch.dtype. 

Реальные half/int8-типы в памяти не хранятся: внутри всё остаётся Vec<f32>, а «тип» задаёт правила приведения, памяти и квантизации.

Типы тензоров — это enum Float32 / Float16 / Int8 с методами памяти, квантизации и симулированного cast. Данные физически всегда f32, но при создании тензора и в DenseLayer::forward значения проходят через cast_value/cast_vec, что имитирует пониженную точность и INT8-inference так же, как в полноценных ML-фреймворках на уровне API.

1. Enum DType


```
pub enum DType {
    Float32,  // полная точность
    Float16,  // half / Tensor Cores
    Int8,     // квантизация
}
```


2. Методы DType

bytes_per_element

Float32 => 4

Float16 => 2

Int8    => 1

Нужен для оценки «сколько бы занял» тензор (логирование, сравнение режимов).

supports_accelerator

Все три варианта возвращают true — в этой симуляции любой dtype «можно» гонять на GPU/Metal. В реальных фреймворках часть типов доступна только на CPU.

is_quantized

matches!(self, DType::Int8)

Флаг: после линейного слоя нужен повторный cast (имитация quantize).

cast_value — ядро симуляции

Float32 => value                                    // без изменений

Float16 => (value * 2048.0).round() / 2048.0      // грубая «сетка» half

Int8    => value.clamp(-127.0, 127.0).round()     // целые в [-127, 127]

Это не настоящий IEEE-754 binary16 и не scale/zero-point квантизация PyTorch. Цель — показать эффект потери точности:

Float16: значения «прилипают» к шагу $1/2048$;
Int8: дробная часть пропадает, большие числа обрезаются.

cast_vec / description

cast_vec — map cast_value по всему слайсу;

description — строка для логов ("Float16 (2 байта, Tensor Cores / TPU)").


3. Связь с Tensor


```
pub struct Tensor {
    pub data: Vec<f32>,  // всегда f32 в RAM
    pub dtype: DType,    // семантика точности
}
```


При создании:


```
pub fn new(data: Vec<f32>, dtype: DType) -> Self {
    let casted = dtype.cast_vec(&data);  // сразу приводим
    Tensor { data: casted, dtype }
}
```


То же для from_slice, zeros, ones.

Приведение типа (как .to(dtype) / .to_kind()):


```
pub fn to_dtype(&self, target: DType) -> Tensor {
    if self.dtype == target {
        self.clone()
    } else {
        Tensor::new(self.data.clone(), target)  // снова cast_vec
    }
}
```

Элементные операции (add, mul, …) сохраняют self.dtype у результата.


4. Использование в DenseLayer

Слой хранит свой dtype:
```
pub struct DenseLayer {
    pub weights: Vec<Vec<f32>>,
    pub bias: Vec<f32>,
    pub dtype: DType,
}

```

Инициализация: веса и bias сразу проходят cast_vec выбранного dtype.

Forward:

```
// 1. Вход (обычно Float32) → dtype слоя
let input_tensor = Tensor::from_slice(input, DType::Float32).to_dtype(self.dtype);

// 2. W @ x
let output = mat_vec_mul(&self.weights, &input_casted)?;

// 3. + bias через Tensor::add (в том же dtype)
let output_tensor = Tensor::from_slice(&output, self.dtype)
    .add(&bias_tensor)?;

// 4. Для Int8 — ещё один cast (пост-квантизация выхода)
if self.dtype.is_quantized() {
    output = self.dtype.cast_vec(&output);
}
```

Итог: при Float16/Int8 и входы, и промежуточные активации «огрубляются» по правилам dtype.


5. Связь с сетью (CatPolicyNetwork)

При создании:

CatPolicyNetwork::new_with_dtype(DType::Float16)

// или

ModelConfig { dtype: DType::Float16, ... }

Оба Dense-слоя (и hidden) создаются с этим dtype. В ModelConfig / save-файле dtype сохраняется вместе с архитектурой.

Градиенты в reinforce_step считаются в «полной» f32-логике (учебное упрощение): dtype влияет в основном на forward и симуляцию inference-точности, а не на настоящий mixed-precision training.
