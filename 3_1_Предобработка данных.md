# ﻿**Предобработка данных (Preprocessing)**

Любой проект машинного обучения лучше начать с предобработки данных - например чтение признаков из stdin, валидация и преобразование в тензор (пример реализации в проекте cat_rl_solid).

В текущем коде предобработка рализована нескольким слоям пайплайна. Это сделано осознанно: проект чистый Rust без tch, поэтому вместо «stdin → tch::Tensor» используется цепочка:

сырые данные → валидация → нормализация → (опционально аугментация) → тензор/вектор признаков → проверка пространства наблюдений

Разберём каждый этап.

1. Валидация при создании объекта (Cat::new)


```
pub fn new(name: impl Into<String>, lives: u8) -> Result<Self, String> {
    let name = name.into();
    if name.is_empty() {
        return Err("Имя кота не может быть пустым".into());
    }
    if lives == 0 || lives > 9 {
        return Err(format!(
            "Количество жизней должно быть от 1 до 9, получено: {}",
            lives
        ));
    }
    Ok(Self { name, lives })
}
```

Это первый уровень предобработки:

Возвращается Result — ошибки обрабатываются явно, без panic!.
Cat::random() тоже проходит через new, поэтому синтетические данные уже валидны.

2. Извлечение признаков (get_state) — ядро preprocessing

/// Нормализованное состояние для RL / ML
pub fn get_state(&self) -> Vec<f32> {
    vec![self.lives as f32 / 9.0]
}
Что происходит:

Берётся сырое значение lives: u8 (1…9).
Приводится к f32.
Нормализуется делением на 9 → получается число в диапазоне [≈0.11, 1.0].

Это аналог to_features() из исходного примера со stdin и tch::Tensor, только:

без имени (в RL-среде имя не нужно);

без внешнего tch — обычный Vec<f32>;

нормализация фиксирована (min-max по известному максимуму жизней).

Именно этот вектор потом идёт в нейросеть как observation.

3. Пространство наблюдений (Space::Box) — контракт на вход
В CatEnv:

observation_space: Space::Box {
    low: vec![0.0],
    high: vec![1.0],
},

Методы:

Rustpub fn contains(&self, value: &[f32]) -> bool { ... }

pub fn sample(&self) -> Vec<f32> { ... }

Смысл:

после get_state() значение должно лежать в [0.0, 1.0];

среда и агент договариваются о формате входа (как в Gymnasium);

невалидное состояние отсекается до forward.

reset() / step() / observation() всегда возвращают результат

 get_state():
 
pub fn observation(&self) -> Vec<f32> {

    self.cat.get_state()
    
}

4. Проверка observation space в модели

В forward_multi_task:


```
Rustlet obs_space = Space::Box {
    low: vec![0.0],
    high: vec![1.0],
};
if !obs_space.contains(state) {
    return Err(AppError::SpaceError(format!(
        "Состояние {:?} не входит в observation_space {}",
        state,
        obs_space.description()
    )));
}
```

Это вторая линия защиты:

даже если кто-то обошёл CatEnv и подал «сырой» вектор;

модель не примет, например, [2.0] или пустой слайс.

Ошибки типизированы через AppError::SpaceError / EmptyTensor.

5. Аугментация как train-time preprocessing

```
let input_state = if self.is_training() {
    if let Some(ref aug) = self.augmenter {
        aug.augment(state)?
    } else {
        state.to_vec()
    }
} else {
    state.to_vec()
};

```

DataAugmenter (CV + NLP стиль):

В конце всегда:
*x = x.clamp(0.0, 1.0);  // остаёмся в observation space

Важно:

аугментации только в Train;
в Eval состояние чистое — честная оценка.

Это стандартный приём ML: предобработка расширяется на этапе обучения.

6. Приведение к «тензору» и dtype

Собственный Tensor (без LibTorch):

pub struct Tensor {
    pub data: Vec<f32>,
    pub dtype: DType,  // Float32 / Float16 / Int8
}

В DenseLayer::forward:

let input_tensor = Tensor::from_slice(input,
 DType::Float32).to_dtype(self.dtype);
 
let input_casted = input_tensor.to_vec();

// дальше matmul + bias через Tensor::add

Предобработка здесь:

вход всегда Vec<f32>;

при необходимости cast в Float16 / Int8 (симуляция half/quantization);

для Int8 — дополнительное округление/клиппинг.

Это замена .to_kind() / .to_dtype() из tch/Burn.

8. Связь с исходным примером из запроса

// stdin → parse → Cat → to_features() → tch::Tensor


```
fn to_features(&self) -> Tensor {
    let name_len = self.name.len() as f32;
    let lives_norm = self.lives as f32 / 9.0;
    Tensor::of_slice(&[name_len, lives_norm])
}
```
