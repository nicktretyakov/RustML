Режимы — аналог model.train() / model.eval() в PyTorch и Burn. Они переключают поведение сети: можно ли обновлять веса и применять ли аугментации.

Режимы — это поле mode: ModelMode (Train | Eval) с методами train() / eval() / is_training(). В Train включаются аугментации и разрешён reinforce_step; в Eval вход чистый, обновление весов отключено. По смыслу это тот же контракт, что model.train() / model.eval() в PyTorch, адаптированный под RL-агента с REINFORCE.

1. Enum ModelMode

```
pub enum ModelMode {
    Train,  // обучение
    Eval,   // оценка / инференс
}

```

Train.train()forward + backprop + аугментации

Eval.eval() только forward обновление весов, аугментации

description() даёт строки для логов:

"TRAIN (обучение + обновление весов)" / "EVAL (только инференс, обновления ЗАПРЕЩЕНЫ)".

2. Поле в CatPolicyNetwork

```
pub struct CatPolicyNetwork {
    // ...
    pub mode: ModelMode,
    // ...
}

```

При создании (from_config / new_with_dtype) по умолчанию:

mode: ModelMode::Train

Режим сохраняется в .model файле вместе с dtype/device (mode: Train / Eval).

3. API переключения


```
pub fn train(&mut self) {
    self.mode = ModelMode::Train;
    println!("🔥 Модель переведена в режим TRAIN");
}

pub fn eval(&mut self) {
    self.mode = ModelMode::Eval;
    println!("📊 Модель переведена в режим EVAL");
}

pub fn is_training(&self) -> bool {
    self.mode == ModelMode::Train
}
```


Типичный сценарий:


```
nn.train();
// ... train_episode / reinforce_step ...

nn.eval();
// ... run_episode / только forward ...
```


4. Где режим реально влияет

A. Аугментации в forward_multi_task


```
let input_state = if self.is_training() {
    if let Some(ref aug) = self.augmenter {
        aug.augment(state)?   // CV/NLP шум только при обучении
    } else {
        state.to_vec()
    }
} else {
    state.to_vec()            // Eval — чистое состояние
};
```

Train возможно зашумлённый state

Eval исходный observation без аугментаций

Иначе метрики на тесте были бы завышены/зашумлены.

B. Обновление весов в reinforce_step

```
pub fn reinforce_step(...) -> Result<(), AppError> {
    if !self.is_training() {
        return Ok(());  // тихий no-op
    }
    // ... градиенты и weight updates ...
}

```
Даже если вызвать reinforce_step в Eval, веса не изменятся.

forward / forward_multi_task / select_action работают в обоих режимах.

C. Циклы обучения vs оценки

train_episode — подразумевает Train (сбор траектории + reinforce_step).

run_episode — только rollout, без обновлений; корректно сочетается с nn.eval().


5. Схема жизненного цикла
 
Создание сети → mode = Train (по умолчанию)

        │
        
        ▼
        
nn.train()

        │
        
        ├─ forward_multi_task → аугментации ON
        
        ├─ train_episode / reinforce_step → веса обновляются
        
        │
        
        ▼
        
nn.eval()

        │
        
        ├─ forward_multi_task → аугментации OFF
        
        ├─ reinforce_step → сразу return (веса заморожены)
        
        └─ run_episode / select_action → честный инференс
        

6. Пример использования


```
let mut nn = CatPolicyNetwork::new_with_dtype(DType::Float32);

// --- обучение ---
nn.train();
for _ in 0..20 {
    let mut env = CatEnv::random();
    let (reward, loss, steps) = nn.train_episode(&mut env, 50, 0.99, 0.008)?;
}

// --- оценка ---
nn.eval();
let mut env = CatEnv::random();
let (reward, steps) = nn.run_episode(&mut env, 50)?;
// reinforce_step здесь ничего не сделает
```
