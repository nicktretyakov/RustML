#### **Простое обучение модели**
По сути, ML-часть проекта — это **учебный пример ручной реализации линейной регрессии с SGD**, обёрнутый в сложную инфраструктуру управления контекстами и мониторинга. Показана базовая математика линейной регрессии и SGD. Есть инфраструктура для сохранения/восстановления состояния. Подготовлена почва для GPU-ускорения через FFI. Собираются метрики и логи. В данном проекте машинное обучение реализовано на **минимально возможном уровне** — это **простая линейная регрессия** без признаков, без реального датасета, без батчинга и без сложных оптимизаторов. Всё сделано исключительно для демонстрации инфраструктуры (контексты, сериализация, мониторинг, FFI к CUDA). Тем не менее, разберём по шагам, как именно работает ML-часть.
#### **1. Что за модель?**
Модель представлена структурой ModelContext:

struct ModelContext {

`    `weights: Vec<f32>,     // веса для каждого признака

`    `bias: f32,             // смещение

`    `optimizer: Optimizer,  // тип оптимизатора: SGD, Adam или Cuda

`    `learning\_rate: f32,    // скорость обучения

`    `metrics: TrainingMetrics, // история лосса и другие метрики

}

- При создании (ModelContext::new(features, optimizer, lr)) веса инициализируются **нулями**, bias = 0.0.

  Это создание новой модели для обучения. Простыми словами — вы запускаете программу, которая будет учиться предсказывать что-то на основе данных.

  - **features** — это признаки, характеристики объекта. Например, если вы предсказываете цену квартиры, то признаками могут быть: площадь, количество комнат, этаж.
  - **optimizer** — это метод, который помогает модели учиться (подбирать веса). Например, как тренер настраивает спортсмена.
  - **lr (learning rate)** — скорость обучения. Если слишком большая — модель будет "перескакивать" через правильные ответы, если слишком маленькая — будет учиться очень долго.

    **Веса (weights, w₁, w₂, ...)** — это числа, которые модель умножает на каждый признак. Сначала они все равны нулю, потому что модель ещё ничего не знает.

    **Bias (b)** — это дополнительное число, которое добавляется к результату. Сначала оно тоже равно нулю.

**Пример:** Представьте, что вы хотите предсказать цену квартиры по её площади. Сначала модель не знает, как площадь влияет на цену, поэтому все веса равны нулю.

- Количество весов равно числу признаков (в примере — 3).

  Если у вас 3 признака (например, площадь, количество комнат, этаж), то и весов будет 3 — по одному на каждый признак.

  **Пример:**

  - Признаки: площадь (x₁), количество комнат (x₂), этаж (x₃)
  - Веса: w₁, w₂, w₃

Это классическая линейная регрессия: **prediction = w₁·x₁ + w₂·x₂ + … + wₙ·xₙ + b**

Это формула, по которой модель делает предсказание. Она умножает каждый признак на свой вес, складывает всё вместе и добавляет bias.

**Пример:** Предскажем цену квартиры:

- Площадь (x₁) = 50 м², вес (w₁) = 1000
- Комнаты (x₂) = 2, вес (w₂) = 50000
- Этаж (x₃) = 5, вес (w₃) = 10000
- Bias (b) = 100000

**Prediction = 1000·50 + 50000·2 + 10000·5 + 100000 = 50000 + 100000 + 50000 + 100000 = 300000** То есть, предсказанная цена квартиры — 300 000 (условных единиц).
#### **2. Прямое распространение (forward pass) — метод predict**
fn predict(&self, features: &[f32]) -> f32 {

`    `self.weights

.iter()

.zip(features.iter())

.map(|(w, f)| w \* f)

.sum::<f32>()

`        `+ self.bias

}

- Принимает вектор признаков той же длины, что и weights.

  Вектор признаков — это набор чисел, которые описывают какой-то объект. Каждое число в этом наборе — это отдельная характеристика (признак) объекта.

  **Пример:** Представьте, что вы описываете квартиру для продажи. Ваши признаки могут быть:

  - Площадь (например, 50 м²)
  - Количество комнат (например, 2)
  - Этаж (например, 3)
  - Расстояние до метро (например, 500 м)

Тогда вектор признаков для этой квартиры будет выглядеть так: **[50, 2, 3, 500]**

Веса — это числа, которые показывают, насколько важен каждый признак для итогового результата. Они подбираются так, чтобы модель могла делать правильные предсказания.

**Пример:** Допустим, вы хотите предсказать цену квартиры. Модель учится и понимает, что:

- Площадь очень важна (вес = 1000)
- Количество комнат важно, но меньше (вес = 50000)
- Этаж почти не важен (вес = 100)
- Расстояние до метро важно (вес = -200, потому что чем дальше, тем дешевле)

Тогда вектор весов будет: **[1000, 50000, 100, -200]**

- Вычисляет скалярное произведение + bias.

  Скалярное произведение — это операция, при которой каждый признак умножается на соответствующий вес, а потом все результаты складываются.

  **Формула:** Если у вас вектор признаков **[x₁, x₂, x₃, x₄]** и вектор весов **[w₁, w₂, w₃, w₄]**, то скалярное произведение = x₁·w₁ + x₂·w₂ + x₃·w₃ + x₄·w₄.

  **Пример:** Для нашей квартиры: 50·1000 + 2·50000 + 3·100 + 500·(-200) = 50000 + 100000 + 300 - 100000 = 50300

  Bias — это просто число, которое добавляется к результату скалярного произведения. Оно нужно, чтобы модель могла сдвигать свои предсказания вверх или вниз.

  **Пример:** Допустим, после скалярного произведения у нас получилось 50300, а bias = -10000. Тогда итоговое предсказание цены квартиры: 50300 + (-10000) = 40300 (например, рублей)

- Никаких нелинейностей, никаких слоёв — чистая линейная модель.

  Это модель, которая только умножает признаки на веса, складывает результаты и добавляет bias. Она не использует никакие сложные преобразования (например, нелинейности), поэтому называется "чистой" и "линейной".

  **Пример:** Если у вас есть данные о квартирах, линейная модель может предсказать цену как: **Цена = (Площадь·вес1 + Комнаты·вес2 + Этаж·вес3 + Расстояние·вес4) + bias**
#### **3. Функция потерь (loss)**
В методе train\_step используется **среднеквадратичная ошибка (MSE)** для одного примера:

let prediction = self.predict(features);

let error = prediction - target;

let loss = error.powi(2);  // (pred - target)²

Это стандартный MSE для регрессии (без деления на 2 или на количество сэмплов, но для обучения это не критично — влияет только на масштаб градиента).

train\_step - это функция (или шаг) в процессе обучения нейронной сети. На каждом таком шаге модель:

- Получает один или несколько примеров (например, картинку с кошкой или таблицу с данными).
- Делает предсказание (например, «на картинке кот»).
- Сравнивает предсказание с правильным ответом.
- Корректирует свои параметры, чтобы в следующий раз ошибаться меньше.

**Пример:** Представьте, что вы учите ребёнка умножать: показываете пример «2×3», он говорит «5», вы говорите «нет, правильный ответ 6», и ребёнок запоминает, чтобы в следующий раз ответить правильно.

Среднеквадратичная ошибка (MSE) - это способ измерить, насколько сильно модель ошиблась. Формула простая:

- Берём разницу между правильным ответом и предсказанием модели.
- Возводим эту разницу в квадрат (чтобы ошибка была всегда положительной и большие ошибки выделялись сильнее).
- Усредняем по всем примерам.

**Пример:** Допустим, модель предсказала цену дома 10 млн, а реальная цена 12 млн. Ошибка = (12 − 10)² = 4. Если бы ошибка была 1 млн, то (12 − 11)² = 1. MSE показывает, что первая ошибка в 4 раза хуже второй.
#### **4. Обратное распространение и обновление весов (backward pass + update)**
В том же train\_step:

let gradient = 2.0 \* error;  // производная MSE по предсказанию

for i in 0..self.weights.len() {

`    `self.weights[i] -= self.learning\_rate \* gradient \* features[i];

}

self.bias -= self.learning\_rate \* gradient;

Разберём аналитически:

- Производная MSE по предсказанию: ∂L/∂pred = 2·(pred − target)

  Это формула, которая показывает, как меняется ошибка (MSE — Mean Squared Error) при изменении предсказания модели.

  **Простыми словами:** MSE — это мера того, насколько предсказание модели отличается от реального значения. Формула показывает, насколько сильно ошибка зависит от предсказания.

  **Пример:** Допустим, модель предсказала, что цена дома — 100 000 рублей, а реальная цена — 120 000 рублей. Тогда ошибка (pred − target) = 100 000 − 120 000 = −20 000. Производная будет равна 2·(−20 000) = −40 000. Это число показывает, насколько сильно нужно изменить предсказание, чтобы уменьшить ошибку.

- Производная предсказания по весу wᵢ: ∂pred/∂wᵢ = xᵢ

  Это формула, которая показывает, как меняется предсказание модели при изменении одного из весов (wᵢ).

  **Простыми словами:** Веса — это параметры модели, которые она подбирает, чтобы делать точные предсказания. Здесь говорится, что изменение предсказания зависит от значения признака (xᵢ).

  **Пример:** Допустим, у вас есть признак "площадь дома" (xᵢ = 50 м²). Если вес для этого признака изменится на 1, то предсказание изменится на 50 (потому что ∂pred/∂wᵢ = xᵢ = 50).

- Производная по bias: ∂pred/∂b = 1

  Это формула, которая показывает, как меняется предсказание модели при изменении смещения (bias).

  **Простыми словами:** Bias — это дополнительный параметр, который сдвигает предсказание вверх или вниз. Здесь говорится, что изменение предсказания зависит от bias напрямую (на 1).

  **Пример:** Если bias изменится на 1, то предсказание изменится на 1 (потому что ∂pred/∂b = 1).

Итоговый градиент:

- по wᵢ: 2·(pred − target)·xᵢ
- по b: 2·(pred − target)

Это формулы, которые показывают, насколько нужно изменить веса и bias, чтобы уменьшить ошибку.

**Простыми словами:** Градиент — это направление и величина, в котором нужно изменить параметры модели, чтобы ошибка стала меньше.

**Пример:** Если ошибка (pred − target) = −20 000, а xᵢ = 50, то градиент по весу wᵢ = 2·(−20 000)·50 = −2 000 000. Это значит, что вес wᵢ нужно увеличить на 2 000 000 (но на практике шаг изменения будет маленьким, например, 0.001).

Обновление — классический **стохастический градиентный спуск (SGD)** без моментума. 

Это метод, который использует вычисленные градиенты, чтобы обновить веса и bias модели.

**Простыми словами:** SGD — это алгоритм, который постепенно подстраивает параметры модели, чтобы она делала всё более точные предсказания. "Без моментума" значит, что изменения зависят только от текущего градиента, а не от предыдущих шагов.

**Пример:** Если градиент по весу wᵢ = −2 000 000, а шаг обучения (learning rate) = 0.001, то вес изменится на −2 000 000·0.001 = −2 000. То есть вес уменьшится на 2 000.

Это **ручная реализация** backpropagation для одного примера. Никаких автодифференцирований (как в PyTorch/TensorFlow) — всё жёстко закодировано под линейную модель.
#### **5. Альтернативное обновление через CUDA — метод update\_with\_cuda**
fn update\_with\_cuda(&mut self, gradients: &[f32], cuda\_ctx: &SafeCudaContext) -> Result<(), ContextError>

- Принимает готовые градиенты (в примере — заглушка vec![0.1; len]).

  Функция получает на вход массив чисел — **градиенты**. Градиенты показывают, насколько нужно изменить каждый параметр (вес) модели, чтобы она стала точнее.

  **Пример:** Представьте, что вы учитесь стрелять из лука. После каждого выстрела тренер говорит: «Стрела ушла слишком влево на 0.1 метра». Это и есть градиент — насколько нужно подкорректировать прицел.

  **Заглушка** vec![0.1; len] В коде вместо реальных градиентов используется упрощённый массив, где все значения равны 0.1. Это как если бы тренер всегда говорил: «Подвинь прицел на 0.1 метра», независимо от результата.

- Проверяет совпадение размеров.

  Функция проверяет, что количество весов и градиентов совпадает. Если весов 100, а градиентов 99 — будет ошибка.

  **Пример:** У вас есть 10 стрелок и 10 советов от тренера. Если советов будет 9 или 11 — что-то пошло не так.

- Вызывает FFI-функцию cuda\_optimizer\_step, передавая указатели на веса, градиенты, длину и lr.

  **FFI (Foreign Function Interface)** — это способ вызвать функцию, написанную на другом языке (например, на C или CUDA).

- cuda\_optimizer\_step — функция, которая обновляет веса модели с использованием видеокарты (GPU).
- **Указатели** — это адреса в памяти, где хранятся веса и градиенты.
- lr **(learning rate)** — шаг обучения, насколько сильно менять веса.

**Пример:** Вы передаёте тренеру список стрелок, список советов, количество стрелок и насколько сильно нужно подкручивать прицел за раз.

- В реальной системе здесь мог бы быть CUDA-код, выполняющий обновление на GPU (например, SAXPY: weights -= lr \* grads).

  **CUDA** — технология, позволяющая использовать видеокарту для быстрых вычислений.

  **SAXPY** — простая операция: weights = weights - lr \* grads.

  **GPU** — видеокарта, которая быстро выполняет такие операции.

**Пример:** Тренер быстро корректирует прицел у всех стрелок одновременно, а не по одной.

В текущем проекте из-за моков в cuda\_mock.c создание SafeCudaContext всегда падает с ошибкой, поэтому этот путь **никогда не выполняется успешно**.
#### **6. Варианты оптимизаторов**
Перечисление Optimizer:

enum Optimizer {

`    `SGD,   // используется ручной код в train\_step

`    `Adam,  // НЕ РЕАЛИЗОВАН совсем

`    `Cuda,  // должен использовать update\_with\_cuda

}

- При выборе SGD или Adam обновление всегда идёт через ручной код в train\_step.

  Это **алгоритмы оптимизации**, которые используются при обучении нейронных сетей (и других моделей машинного обучения). Их задача — подбирать такие значения параметров модели (например, весов нейронов), чтобы модель давала как можно более точные предсказания.

  - **SGD (Stochastic Gradient Descent — стохастический градиентный спуск):** Представьте, что вы стоите на вершине холма и хотите спуститься в самую низкую точку. Вы делаете маленькие шажки в сторону самого крутого спуска. Иногда можете споткнуться или пойти не в ту сторону, но в целом движетесь к цели. **Пример:** Если модель предсказывает цену дома, SGD будет постепенно подстраивать веса, чтобы ошибка предсказания становилась меньше.
  - **Adam (Adaptive Moment Estimation):** Это более продвинутый алгоритм, который не только смотрит, в какую сторону спускаться, но и запоминает, как быстро вы двигались раньше, и подстраивает шаги. Он как бы "учится" на своих ошибках и может быстрее и точнее найти оптимальные параметры. **Пример:** Если SGD — это спуск с холма с завязанными глазами, то Adam — это спуск с картой и компасом, который учитывает рельеф и скорость ветра.

    **train\_step** — это функция (кусочек кода), которая описывает, как именно происходит одно "обучение" модели на небольшой порции данных (батче).

  - **"Ручной код"** означает, что программист сам написал, как именно обновлять веса модели, не полагаясь на стандартные библиотеки (например, PyTorch или TensorFlow). **Пример:** Вместо того, чтобы просто вызвать optimizer.step().
- При Cuda — только через FFI (но в проекте падает).

Adam в коде вообще не реализован — это просто заглушка для будущего расширения.
#### **7. Тренировочный цикл (в функции train\_model)**
for epoch in 0..100 {

`    `let loss = model.train\_step(&features, target)?;



`    `if epoch % 10 == 0 {

`        `let gradients = vec![0.1; model.weights.len()];

`        `model.update\_with\_cuda(&gradients, &cuda\_ctx)?;

`    `}



`    `record\_metric("epoch\_loss", loss as f64);

}

Ключевые особенности:

- **Один фиксированный сэмпл** на все 100 эпох:

  let features = vec![1.0, 2.5, 0.5];

  let target = 4.0;

  Это не реальное обучение — модель просто бесконечно подгоняется под одну точку.

- Нет валидации, нет early stopping.

  **Валидация** — это проверка модели на данных, которые не использовались для обучения. Представьте, что вы учитесь решать задачи по математике (обучение), а потом решаете контрольную работу (валидация), чтобы понять, насколько хорошо вы усвоили материал.

  **Early stopping** — это остановка обучения модели, если она перестаёт улучшаться на валидационных данных. Например, если вы решаете контрольную и видите, что ошибки не уменьшаются, то дальше учиться бессмысленно — пора остановиться.

  **Что значит "нет валидации, нет early stopping"?** Модель обучается без проверки на новых данных и без автоматической остановки. Это как учиться без контрольных и без учителя, который скажет: "Хватит, дальше только хуже!"

- Каждые 10 эпох пытается обновить веса через CUDA (в реальности упадёт).

  **Эпоха** — это один полный проход по всем данным для обучения. Например, если у вас 100 карточек для запоминания, одна эпоха — это просмотр всех 100 карточек один раз.

- **Что значит "попытка обновить веса через CUDA"?** Каждые 10 эпох модель пытается улучшить свои параметры с помощью видеокарты. Но в тексте сказано, что "в реальности упадёт" — то есть на практике это не сработает (например, из-за ошибок в коде или нехватки памяти).
- Лосс и другие метрики записываются в глобальный MonitoringSystem.

  **Лосс (Loss)** — это ошибка модели. Чем меньше лосс, тем лучше модель справляется с задачей. Например, если модель предсказывает цену дома, лосс — это разница между реальной ценой и предсказанной.

- **Метрики** — это другие показатели качества модели (например, точность, полнота, F1-мера).
- **MonitoringSystem** — это система, которая собирает и хранит все эти показатели, чтобы можно было отслеживать, как модель обучается.
- **Что значит "записываются в глобальный MonitoringSystem"?** Все ошибки и метрики автоматически сохраняются в общую систему мониторинга, чтобы их можно было потом проанализировать (например, построить графики или таблицы).
#### **8. Метрики и мониторинг**
В train\_step после обновления:

self.metrics.loss\_history.push(loss);

record\_metric("loss", loss as f64);

record\_metric("learning\_rate", self.learning\_rate as f64);

В конце main печатается отчёт со средними значениями метрик и временными трассами.
#### **9. Сериализация состояния модели**
ModelContext реализует трейт SerializableContext, поэтому всю модель (веса, bias, optimizer, метрики) можно:

- сохранить на диск через bincode,
- загрузить обратно.

Это позволяет, например, прерывать обучение и продолжать позже.

**Context ML OOП**
### **Реализация ООП**
Используется **динамический полиморфизм** через Box<dyn Trait> для абстрагирования оптимизаторов.
#### **1.** Инкапсуляция (Encapsulation)
- Все данные и поведение объединены в структуры.
- Примеры:
  - LinearModel инкапсулирует состояние модели (weights: Array1<f32>, bias: f32) и поведение (методы predict\_parallel, train\_batch, evaluate).
  - AdamOptimizer инкапсулирует внутреннее состояние моментов (m\_weights, v\_weights, m\_bias, v\_bias, t) — эти поля приватны (по умолчанию в Rust), доступ только через методы.
  - StandardScaler инкапсулирует параметры нормализации (mean, scale).
- Публичные методы предоставляют контролируемый доступ, скрывая детали реализации (например, как именно обновляются веса в Adam).
#### **2.** Абстракция и Полиморфизм (Abstraction & Polymorphism)
- Центральный элемент — **трейт OptimizerImpl**:

  pub trait OptimizerImpl: Send + Sync {

  `    `fn update\_weights(

  `        `&mut self,

  `        `weights: &mut Array1<f32>,

  `        `bias: &mut f32,

  `        `grad\_weights: &Array1<f32>,

  `        `grad\_bias: f32,

  `        `lr: f32,

  `        `cuda\_ctx: Option<&cuda\_safe::SafeCudaContext>,

  `    `);

  }

  Это абстрактный интерфейс (аналог abstract class/interface в классическом ООП).

  - Send + Sync — обеспечивает безопасную передачу между потоками (конкурентность).
- Конкретные реализации (полиморфизм):
  - SGDOptimizer, AdamOptimizer, CudaOptimizer реализуют трейт (impl OptimizerImpl for ...).
  - В LinearModel используется **динамический полиморфизм**:

    optimizer: Box<dyn OptimizerImpl>,

    Это runtime-полиморфизм (vtable как в C++). Модель не знает конкретный тип оптимизатора — только абстракцию.

При создании модели:

let optimizer: Box<dyn OptimizerImpl> = match optimizer\_type {

`    `"SGD" => Box::new(SGDOptimizer { lr }),

`    `"Adam" => Box::new(AdamOptimizer::new(features, lr)),

`    `"Cuda" => Box::new(CudaOptimizer),

`    `\_ => panic!("Unknown optimizer"),

};

Это **фабричный паттерн** (Factory) — выбор конкретной реализации на основе строки.
#### **3.** Композиция вместо наследования (Composition over Inheritance)
- Модель **компонует** оптимизатор (optimizer: Box<dyn OptimizerImpl>), а не наследует от него.
- Trainer компонует LinearModel, данные и CUDA-контекст.
- Это предпочтительный подход в Rust/OOP: легче тестировать, избегать хрупкой иерархии наследования.

**Подробное объяснение реализации принципов SOLID в коде**
#### SOLID-принципы в реализации
- **S — Single Responsibility Principle (Принцип единственной ответственности)** Каждая структура отвечает только за одну вещь:
  - LinearModel — только модель и предсказания/обучение на батче.
  - AdamOptimizer / SGDOptimizer / CudaOptimizer — только логика обновления весов.
  - StandardScaler — только предобработка (fit/transform).
  - Trainer — оркестрация обучения (батчинг, shuffling, логирование метрик).
  - MonitoringSystem — только сбор и отчёт метрик (singleton через lazy\_static).
- **O — Open-Closed Principle (Принцип открытости/закрытости)** Система открыта для расширения, закрыта для модификации:
  - Чтобы добавить новый оптимизатор (например, RMSProp), достаточно создать новую структуру и impl OptimizerImpl for NewOptimizer.
  - Не нужно менять LinearModel или Trainer — они зависят только от трейта.
  - Аналогично для новых моделей или препроцессоров.
- **L — Liskov Substitution Principle (Принцип подстановки Барбары Лисков)** Любая реализация OptimizerImpl может быть подставлена вместо другой без нарушения поведения.
  - Все оптимизаторы принимают одинаковые параметры и выполняют одну задачу (обновление весов).
  - Нет "странного" поведения в подклассах.
- **I — Interface Segregation Principle (Принцип разделения интерфейсов)** Трейт OptimizerImpl маленький и сфокусированный — только один метод update\_weights.
  - Нет "жирных" интерфейсов с лишними методами.
- **D — Dependency Inversion Principle (Принцип инверсии зависимостей)** Высокоуровневые модули (LinearModel, Trainer) зависят от абстракций (OptimizerImpl), а не от конкретных реализаций.
  - Конкретные оптимизаторы зависят только от низкоуровневых деталей (ndarray, CUDA FFI).
  - Инверсия: детали зависят от абстракций.

**Конкурентность**
#### Конкурентность и потокобезопасность в ООП-контексте
- Трейт требует Send + Sync — все реализации оптимизаторов потокобезопасны.
- MonitoringSystem — singleton (паттерн Singleton) через lazy\_static! и Arc<Mutex<...>> для безопасного доступа из разных потоков.
- Конкурентность в предсказаниях:

  let preds: Vec<f32> = (0..X.nrows())

      .into\_par\_iter()  // rayon: параллельные потоки

      .map(|i| X.row(i).dot(&self.weights) + self.bias)

      .collect();

  Это параллелизм на уровне данных (data parallelism) — классический приём в ML.
#### **Итоговая архитектура**
Trainer (оркестратор)

` `└── LinearModel (ядро модели)

`     `└── Box<dyn OptimizerImpl> (полиморфизм)

`         `├── SGDOptimizer

`         `├── AdamOptimizer (сложная внутренняя состояние)

`         `└── CudaOptimizer (интеграция с FFI)

` `└── StandardScaler (предобработка)

` `└── MonitoringSystem (singleton, потокобезопасный)
